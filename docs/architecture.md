# Архитектура FSP Match Platform

## Назначение

Веб-платформа обратного подбора ИТ-специалистов: кандидат проходит опрос и квалификационный тест → получает категорию (специализация × грейд); работодатель ищет по категории, видит объяснимый ранг и отправляет **адресное приглашение** конкретному человеку.

## Слои

```
┌─────────────┐     HTTPS/JWT      ┌──────────────────┐
│  Next.js    │ ◄────────────────► │  FastAPI (API)   │
│  (frontend) │   /api/*           │  модульный       │
└─────────────┘                    │  монолит         │
                                   └────────┬─────────┘
                                            │ SQLAlchemy
                                   ┌────────▼─────────┐
                                   │ PostgreSQL 16    │
                                   └──────────────────┘
```

| Компонент | Путь | Ответственность |
|-----------|------|-----------------|
| Frontend | `frontend/src/app/` | Кабинеты кандидата и работодателя, регистрация |
| API | `backend/app/api/routes/` | Auth, профили, тест, match, приглашения |
| Доменная логика | `backend/app/services/` | Тест (антислив), ранжирование, reason |
| Модели | `backend/app/models/` | User, Candidate, Employer, Category, Test, Invitation |
| Безопасность | `backend/app/core/` | JWT, bcrypt, 152-ФЗ (согласие, контакты) |

## Роли и потоки данных

1. **Кандидат:** register → consent 152-ФЗ → профиль → survey (спец + грейд) → test/start → test/submit → category.
2. **Работодатель:** company → need (опционально) → match (фильтры) → invitation → статусы; контакты кандидата только после `accepted`.
3. **ФСП:** поле `fsp_id` + таблица-заглушка `fsp_achievements`; влияет на **ранг**, не на грейд.

## Развёртывание

- **БД:** локальный PostgreSQL (pgAdmin) или сервис `db` в Docker Compose.
- **Локально:** создать БД через `backend/scripts/init_pg.sql` → `python seed.py` → uvicorn + `npm run dev`.
- Пул соединений SQLAlchemy: `pool_size=10`, `max_overflow=30`.

## Границы MVP

- Нет исполнения кода в песочнице, прокторинга, чата, ATS.
- Auth — собственный JWT (имитация FSP ID / Keycloak описана в `fsp.md`).
- OpenAPI генерируется FastAPI: `/docs` на API.
