# Интеграция с FSP ID (имитация)

## Текущее состояние продукта

Боевого API FSP ID и Keycloak на хакатоне нет. Платформа реализует **демонстрационную привязку**:

1. Кандидат вводит строку `fsp_id` в профиле (`PATCH /api/candidate/profile`).
2. Backend ищет записи в `fsp_achievements` по этому id.
3. Если найдены — `has_fsp_history=true`, `fsp_score` = сумма `points`.
4. Если нет — `has_fsp_history=false`, `fsp_score=0` (кейс «истории нет» обработан в UI и в `reason` подбора).

Достижения **не меняют грейд**, только ранг внутри категории.

## Целевая схема (после хакатона)

```
┌──────────┐   OAuth2/OIDC    ┌─────────────┐
│ Браузер  │ ───────────────► │  Keycloak   │
│          │ ◄─────────────── │  (FSP ID)   │
└────┬─────┘   id_token       └──────┬──────┘
     │                               │
     │ JWT / session                 │ REST (будущее)
     ▼                               ▼
┌────────────────────────────────────────────┐
│           FSP Match API                     │
│  - привязка sub ↔ candidate                 │
│  - периодический sync achievements          │
└────────────────────────────────────────────┘
```

### Планируемые шаги

| Этап | Действие |
|------|----------|
| 1 | Login через OIDC (authorization code), маппинг `sub` → `User` |
| 2 | Сервис `FspAchievementProvider`: HTTP-клиент к API ФСП (когда появится контракт) |
| 3 | Кэш достижений в `fsp_achievements`, TTL и инвалидация по webhook |
| 4 | Аудит: только подтверждённые из FSP поля в ранжировании |

### Поля достижений (ориентир из Q&A)

- Название соревнования / дисциплина  
- Место, разряд  
- Дата (`achieved_at`) — опционально для веса «свежести»  
- Баллы для ранга (`points`)

Демо-сиды: `FSP-1001`, `FSP-1002`, `FSP-2001` в `seed.py`.
