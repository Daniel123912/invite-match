# Черновик структуры презентации (питч 5 мин)

Формат: pptx/pdf, 8–10 слайдов. Ниже — тезисы для спикера.

## 1. Проблема (30 сек)

- Классический отклик: шум, недостоверные грейды, контакты «в открытую».
- Работодателю нужен **проверенный** уровень и объяснимый шортлист.
- Участники ФСП имеют подтверждённые достижения, но нет моста к найму.

## 2. Решение: обратная механика (40 сек)

- Кандидат: опрос → тест → **категория**.
- Работодатель: категория → подборка с `reason` → **адресное приглашение** с зарплатой.
- Контакты открываются только после accept.

## 3. Тест и категоризация (60 сек) — критерий 25%

- Грейд даёт только тест (≥60%), не резюме и не ФСП.
- Антислив: варианты **A/B**, каждому — свой набор из одной группы.
- Кулдаун смены грейда 90 дней; без принудительного понижения.
- Демо: `new@demo.ru` проходит путь за 2–3 минуты.

## 4. Подбор (60 сек) — критерий 35%

- `rank = 0.7×тест + 0.3×ФСП`.
- Текст «почему в подборке».
- Нет ФСП → не выкидываем, ранжируем по тесту.
- Неподтверждённый грейд виден, но ниже.

## 5. Живое демо (90 сек)

1. Кандидат: тест → категория.
2. Работодатель: фильтр Backend Middle → reason → invite.
3. Кандидат: accept → контакты у работодателя.

Аккаунты: см. README (`demo1234`).

## 6. Валидация (30 сек)

- Свой эталон: таблица «потребность → топ» + pytest.
- Жюри может пройти тест с нуля, не только смотреть демо.

## 7. FSP ID и 152-ФЗ (20 сек)

- Имитация привязки FSP ID + скелет OIDC/Keycloak.
- Согласие, скрытие контактов, отзыв доступа.

## 8. Roadmap (20 сек)

Песочница кода, задания работодателей, ATS-экспорт, боевой FSP ID — уже частично как плюсы в прототипе.

## 9. Закрытие

«Работодатель приглашает категоризированного кандидата после теста — это и есть наш MVP.»
