# Механика подбора и категоризация

## Обратная механика

Работодатель **сам** находит категорию и адресно приглашает кандидата. Кандидат попадает в категорию только после опроса + успешного теста.

```
Опрос + тест → Category (спец × грейд)
                     ↓
Работодатель: потребность / фильтры → подборка
                     ↓
Ранжирование + текст reason → приглашение (зарплата от–до)
                     ↓
Кандидат accept / decline → контакты только после accept
```

## Формула ранжирования

```
rank_score = test_score × 0.7 + min(fsp_score, 100) × 0.3
```

- **test_score** — результат квалификационного теста (0–100).
- **fsp_score** — баллы заглушки достижений ФСП по `fsp_id`.
- Если истории ФСП нет: `has_fsp_history=false`, в `reason` явно: «истории ФСП нет — ранжирование по тесту».

## Неподтверждённый грейд

По рекомендации Q&A: кандидат с непройденным/неподтверждённым грейдом **виден** в выдаче, но опускается (`× 0.55`) и помечается в `reason` («грейд не подтверждён тестом»).

## Обоснование (`reason`)

Примеры:

- `тест 85%; ФСП 72 баллов; стек: Python, FastAPI`
- `грейд не подтверждён тестом — ниже в выдаче; тест 55%; истории ФСП нет — ранжирование по тесту`

## Фильтры работодателя

Специализация, грейд, стек (подстроки через запятую), «только с ФСП», привязка к сохранённой потребности (`need_id`).

## Видимость

- В подборке — публичный профиль без телефона/email.
- Контакты открываются **пригласившему** работодателю после `accepted`.
- Кандидат может отозвать доступ к контактам (плюс к 152-ФЗ).
- Зарплата в приглашении обязательна, с пометкой gross/net.

## Как объяснить жюри (30 сек)

«Категория = тест. Внутри категории сортируем 70% тест + 30% ФСП и пишем почему человек в топе. Работодатель зовёт конкретного человека с вилкой зарплаты.»
