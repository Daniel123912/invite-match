# Механика тестирования и присвоения грейда

## Принципы (из Q&A с жюри)

- **Грейд присваивает только первичный тест** по выбранной категории (специализация × уровень), не резюме и не достижения ФСП.
- Кандидат **сам выбирает целевой грейд** в опросе; тест подтверждает или нет.
- При провале **принудительного понижения нет** — сохраняется прежний подтверждённый грейд/категория, если они были.
- Повторная смена подтверждённого грейда — не чаще **1 раза в 90 дней** (`grade_change_cooldown_days`).
- Порог успеха: **≥ 60%** правильных ответов в попытке.

## Банк заданий и устойчивость к «сливу»

### Каноническое хранение

Все формулировки хранятся в БД (`test_questions`): у каждой записи фиксированный `id`, текст, варианты (`options_json`), `correct_index`.  
**Один и тот же `question_id` у всех кандидатов всегда даёт идентичный текст и варианты** — задания не «расходятся» между пользователями.

### Вариантные группы (антислив)

На категорию (например Backend × Middle) заведены параллельные наборы **variant_group** `A` и `B` — разные вопросы на те же темы. При `POST /candidate/test/start`:

1. Случайно выбирается группа (`A` или `B`).
2. Из неё случайно берётся до **5** вопросов.
3. В попытку сохраняются `variant_group` и список `question_ids` — воспроизводимость для аудита.

Кандидаты редко получают одинаковый набор; утечка одного варианта не раскрывает весь банк. Правильные индексы **не отдаются** в API (`QuestionOut` без `correct_index`).

### Сиды

Скрипт `backend/seed.py` наполняет категории Backend/Frontend × Junior/Middle/Senior (демо-объём для хакатона).

## Жизненный цикл попытки

| Шаг | API | Эффект |
|-----|-----|--------|
| Опрос | `POST /candidate/survey` | `specialization`, `selected_grade` |
| Старт | `POST /candidate/test/start` | `TestAttempt`, выдача вопросов |
| Сдача | `POST /candidate/test/submit` | `score`, `passed`, обновление кандидата |

При `passed=true`: `confirmed_grade = selected_grade`, `category_id` = категория попытки, `last_grade_change_at` = now.  
При `passed=false`: `test_score` обновляется, подтверждённая категория не сбрасывается.

## Неподтверждённый грейд

Если кандидат сдал тест ниже порога, он остаётся в подборке по своей специализации и **целевому** грейду со статусом «не подтверждён» и пониженным рангом (см. `match.md`).

## Реализация в коде

- `backend/app/services/test_service.py` — старт, проверка ответов, кулдаун.
- `backend/app/models/` — `TestQuestion`, `TestAttempt`, `Category`.
