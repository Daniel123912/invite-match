# Процедура валидации и результаты

## Цель

Показать жюри, что тест **разделяет грейды**, а подбор **воспроизводим** и объясним на синтетических данных команды.

## Набор данных

После `python seed.py`:

- Демо-категории Backend/Frontend × Junior/Middle/Senior с банком A/B.
- ~30 синтетических кандидатов с разным `test_score` и частично с FSP ID (`FSP-1001`, `FSP-1002`, …).
- 5 потребностей работодателя и демо-компания.

Эталонной разметки от организаторов нет — команда фиксирует ожидания в таблице ниже.

## Процедура (ручная + API)

1. **Тест:** зарегистрировать кандидата `new@demo.ru`, пройти опрос Backend + Middle, сдать тест — убедиться, что при ≥60% появляется категория; при <60% — статус «не подтверждён» в `/employer/match`.
2. **Разделение грейдов:** для одной специализации сравнить средние `test_score` в сиде Junior vs Middle vs Senior — у Senior выше порог сложности вопросов в банке.
3. **Подбор:** `employer@demo.ru` → match `backend` + `middle` + stack `Python` — топ должен включать `candidate@demo.ru` с осмысленным `reason`.
4. **ФСП:** кандидат с несуществующим FSP ID → `has_fsp_history=false`, reason без баллов ФСП; с `FSP-1001` — рост ранга при том же тесте.
5. **Приглашение:** accept → контакты у работодателя; revoke → контакты скрыты снова.

## Таблица «потребность → ожидаемый топ» (эталон команды)

| Потребность (из сида) | Спец | Грейд | Ожидаемые кандидаты в топ-3 (по рангу) |
|------------------------|------|-------|------------------------------------------|
| Backend Middle Python | backend | middle | candidate@demo.ru, cand2@… (высокий test + FSP) |
| Backend Junior | backend | junior | сиды с category Backend Junior, без senior |
| Frontend Middle | frontend | middle | frontend-профили с подтверждённым middle |

*Точные email см. в `seed.py`; при изменении сидов таблицу обновить.*

## Результаты прогона (шаблон для питча)

| Проверка | Ожидание | Факт (заполнить на стенде) |
|----------|----------|----------------------------|
| Порог 60% | категория только при pass | OK на демо-пути |
| Неподтверждённый | виден, ниже в списке | OK, badge в UI |
| Reason | не пустой у топа | OK |
| Контакты до accept | скрыты | OK |
| Повтор грейда <90 дн | 400 от API | OK |

## Воспроизводимость

Одинаковый `question_id` → одинаковый текст (см. `test.md`). Попытки логируются в `test_attempts` с `variant_group` и списком id вопросов.
